## English summary

**SR-BOT** is a self-hosted Telegram shop bot for selling VPN configs (Xray / V2Ray) with a full web admin panel, a Telegram Mini App and a reseller system. It connects to **x-ui / 3x-ui**, **Marzban** and **PasarGuard** panels, sells fixed plans or custom volume/duration, handles wallet top-ups (card-to-card with receipt review, NowPayments crypto, HooshPay), test accounts, renewals, auto-delete of expired configs, per-topic report groups, backups and **one-click self-update from this GitHub repository**. Pure PHP 8 + MySQL, no Composer/Node/Docker; runs on a VPS or shared hosting. Interface language is Persian.

- داشبورد فروش، مدیریت پنل‌ها (تست اتصال، اینباندها/گروه‌ها، نودها)، محصولات، کاربران، سرویس‌ها، پرداخت‌ها

## 🖥 نصب روی سرور (VPS)

روی Ubuntu 20/22/24 یا Debian 11/12:

```bash
# پیش‌نیازها
apt update && apt install -y nginx php-fpm php-mysql php-curl php-mbstring php-zip php-xml mariadb-server unzip cron certbot python3-certbot-nginx

# فایل‌ها
mkdir -p /var/www/srbot && cd /var/www/srbot
unzip /root/SR-BOT-*.zip -d . && mv SR-BOT-*/* . 2>/dev/null; chown -R www-data:www-data /var/www/srbot

# دیتابیس
mysql -e "CREATE DATABASE srbot CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci; CREATE USER 'srbot'@'localhost' IDENTIFIED BY 'STRONG_PASS'; GRANT ALL ON srbot.* TO 'srbot'@'localhost'; FLUSH PRIVILEGES;"

# nginx: نمونهٔ آماده
cp nginx.conf.sample /etc/nginx/sites-available/srbot && ln -s /etc/nginx/sites-available/srbot /etc/nginx/sites-enabled/
# دامنه و مسیر را در فایل ویرایش کنید، بعد:
nginx -t && systemctl reload nginx && certbot --nginx -d bot.example.com
```

سپس در مرورگر `https://bot.example.com/install/` را باز کنید و نصاب وب را دنبال کنید (پایین را ببینید). در پایان **کران‌جاب** را اضافه کنید:

```bash
*/5 * * * * php /var/www/srbot/cron/tasks.php >/dev/null 2>&1
```

## 🌐 نصب روی هاست اشتراکی (سی‌پنل / دایرکت‌ادمین)

1. فایل‌ها را در `public_html` (یا پوشهٔ دامنه) آپلود و از حالت زیپ خارج کنید.
2. در سی‌پنل یک **دیتابیس MySQL** و یک **کاربر** بسازید و کاربر را با تمام دسترسی‌ها به دیتابیس وصل کنید.
3. در مرورگر باز کنید: `https://your-domain.com/install/`
4. نصاب وب در ۵ مرحله راهنمایی می‌کند:
   - بررسی پیش‌نیازها (نسخهٔ PHP، افزونه‌ها، دسترسی نوشتن)
   - اطلاعات دیتابیس (با تست اتصال زنده)
   - توکن ربات (اعتبارسنجی خودکار با تلگرام)
   - ساخت حساب مدیر پنل + نام فروشگاه
   - پایان: ساخت `config.php`، ساخت جداول و تنظیم وب‌هوک
5. در بخش **Cron Jobs** هاست، این دستور را با فاصلهٔ ۵ تا ۱۵ دقیقه اضافه کنید:
   ```
   php /home/USER/public_html/cron/tasks.php
   ```
6. پوشهٔ `install` پس از نصب **خودکار** حذف می‌شود؛ اگر باقی ماند دستی حذف کنید.

> هاست باید **PHP 8.1+**، افزونه‌های `pdo_mysql`, `curl`, `mbstring`, `json`, `zip` و دسترسی به `api.telegram.org` داشته باشد. اگر سرور ایران است و تلگرام مسدود است، از هاست/سرور خارج یا پروکسی استفاده کنید.

## ⚙️ افزودن پنل (x-ui / 3x-ui / Marzban / PasarGuard)

پنل مدیریت → **پنل‌ها** → افزودن:

| فیلد | نمونه |
|---|---|
| نوع پنل | `3x-ui` / `x-ui` / `marzban` / `pasarguard` |
| پروتکل / هاست / پورت | `https` , `panel.example.com` , `2053` |
| مسیر وب (پچ) | `mypath` — اگر ندارید **خالی** |
| یوزر / پسورد | همان اطلاعات ورود پنل |
| لینک ساب | `https://panel.example.com:2096/sub` |
| کد اینباندها / گروه‌ها | x-ui: `1,2` — PasarGuard: نام یا شناسهٔ گروه، یا خالی و انتخاب از فهرست |
| حجم اکانت تست (MB) | `200` — خالی = تست خاموش برای این سرور |
| محدودیت ساخت یوزر | `-1` = نامحدود |

سپس **تست اتصال** را بزنید؛ در صورت موفقیت تعداد اینباندها/گروه‌ها و نودها نمایش داده می‌شود.

> **PasarGuard:** ساخت کاربر بدون گروه ممکن نیست. اول در پنل PasarGuard یک Group با اینباندهای دلخواه بسازید. اگر با کاربر غیر sudo وصل می‌شوید، به آن کاربر دسترسی `groups.read` بدهید یا شناسهٔ گروه را دستی وارد کنید (ربات در صورت خطای 403 گروه را از روی پاسخ پنل استنتاج می‌کند). مستندات: <https://docs.pasarguard.org/en/panel/groups>

## ⚡️ درگاه خودکار ارزی (NowPayments)

1. در حساب NowPayments از مسیر `Store settings → API keys` یک کلید API بسازید.
2. از مسیر `Store settings → IPN` مقدار **IPN secret key** را بردارید و آدرس Callback را ثبت کنید: `https://دامنه-شما/nowpay.php`
3. پنل مدیریت → درگاه‌ها → «⚡️ درگاه خودکار ارزی»: کلید API، IPN Secret، ارز پیش‌فرض (مانند `usdttrc20`) و حداقل مبلغ.
4. دکمهٔ «🔌 تست اتصال و کلید» صحت کلید را بررسی می‌کند.

پرداخت‌ها **خودکار** تایید و کیف پول شارژ می‌شود. اگر IPN نرسد، دکمهٔ «🔄 بررسی وضعیت پرداخت» در ربات و پیگیری خودکار کران‌جاب پشتیبان هستند. درگاه **HooshPay** (`hooshpay.php`) هم به همین شکل در صفحهٔ درگاه‌ها تنظیم می‌شود.

## 🔄 به‌روزرسانی از گیت‌هاب

پنل مدیریت → **به‌روزرسانی**:

| تب | کار |
|---|---|
| **منبع** | مخزن (`owner/repo` یا آدرس کامل گیت‌هاب)، شاخه (خالی = شاخهٔ پیش‌فرض)، پوشهٔ داخلی (اگر `version.json` در زیرپوشه است)، توکن (فقط مخزن خصوصی) |
| **خانه** | «بررسی نسخهٔ جدید» → مقایسهٔ بیلد فعلی و بیلد مخزن، لیست تغییرات، «جزئیات بررسی» (آدرس، کد HTTP، شاخهٔ کشف‌شده)، نصب یک‌دکمه‌ای |
| **نصب از فایل** | آپلود zip ریلیز |
| **دیتابیس** | مایگریشن‌های اجرا‌شده/اجرا‌نشده |
| **تاریخچه** | نسخه‌های قبلی و بازگشت |

جریان نصب: بکاپ → دریافت zip → جایگزینی فایل‌ها (به‌جز `config.php` و `storage/`) → مایگریشن → اسکن دکمه‌های ربات → اعلان در تاپیک به‌روزرسانی. کران‌جاب هم روزانه نسخهٔ تازه را بررسی و به مدیر اطلاع می‌دهد.

> مخزن خصوصی: یک **Fine-grained token** با مجوز `Contents: Read` بسازید. بدون توکن، پیام «فایل version.json در مخزن نیست» می‌بینید.

خط فرمان:

```bash
php cli.php version        # نسخه و بیلد فعلی
php cli.php check          # بررسی نسخهٔ جدید
php cli.php update         # دریافت و نصب
php cli.php backup [full]  # بکاپ دیتابیس / کامل
php cli.php restore <file> # بازگردانی
php cli.php migrate        # مایگریشن‌های اجرانشده
php cli.php prune 7        # پاک‌سازی بکاپ‌های قدیمی
```

| Cloudflare Error 1014 | رکورد CNAME به دامنهٔ دیگری در Cloudflare اشاره می‌کند؛ از رکورد A یا دامنهٔ خود استفاده کنید |
| `Something went wrong (invalid character 'C')` | پاسخ پنل HTML است نه JSON — آدرس/پچ پنل یا صفحهٔ ورود را بررسی کنید |

ابزار تشخیص: `https://your-domain.com/dbdiag.php` (فقط مدیر واردشده یا با `diag_token` در config.php) و `bash tools/lint.sh` برای بررسی سینتکس.
